# TR7-SPARK — independent review (merged)

**Date:** 2026-11-13
**Reviewers:** GLM-5.3-Flash and DeepSeek-V4.1-Flash, both independently
reading the repository; findings below were then re-checked against the source
and, where marked, reproduced with the checked build.
**Scope:** README, all docs, `tr7/src`, `tr7i`, `tr7_c`, scripts, tests, project
files, git history and the existing `gnatprove.out`. Reviews were read-only;
no reviewer ran the build or the prover.
**State reviewed:** `master`, gate green at 3,601 checks, 48 suites reported by
the test script (45 `.scm` suites plus stress/ABI runs).

---

## 1. Executive summary

TR7-SPARK has an unusually disciplined verified core. The handle/generation
model is coherent, the CEK evaluator is compact, and the collector's split
between a worklist drain and a read-only closure check is a credible way to
prove “reachable ⇒ marked ⇒ not swept”. Both reviewers independently found the
collector and the C ABI boundary to be the strongest parts of the project, and
neither found a critical memory-safety, GC-soundness or proof-soundness defect.

The “verified” label must still be read narrowly: what is proved is mostly
memory safety, initialization, aliasing, termination of selected units, and the
collector's closure/reachability properties. Primitive semantics, reader/writer
round-tripping, special-form scope rules, `sqrt` correctness and `%g`
formatting are tested, not proved.

Both reviews converge on the same urgent themes:

1. **Silent numeric wrong answers**: exact `/` drops the tail of a chain once a
   step becomes inexact, unary flonum division is rejected, and `expt` has a
   wrong sign for `-1` with large odd exponents.
2. **Cyclic data can hang the interpreter**: `memq`/`memv`/`assq`/`assv` and
   several syntax walkers (`case`, `do`, `map`) loop without a bound, in one
   evaluator step, so the step limit never fires.
3. **`write` does not produce readable data** for strings or symbols, and
   `#(...)`/`#u8(...)` are expression sugar rather than datum literals, so
   read/write round-tripping of two core datum types fails.
4. **Verification and documentation claims overreach** in a few places:
   warnings are not zero, “every operation has a Pre/Post pair” is not literal,
   the suite count and line count are stale, and one performance narrative
   contradicts the policy file.

The rest are conformance and robustness gaps: named `let`, variadic
`string-append`/`string=?`, improper final `append`, `let` duplicate-binding
locations, unequal-length `map`, float guard false positives, environment depth
limit, long-line source handling, and GC headroom.

## 2. Verification assessment

### Proved

- Arena/handle integrity: `Live_Cell`'s post, `Valid_Handle`, generation
  discipline, and free-list accounting (`Allocate`/`Release` posts).
- Collector success path: `Collect` establishes `Closed_Car`/`Closed_Cdr`/
  `Closed_Env`, `Roots_Marked`, and marked-implies-live when it does not set
  `Mark_Failed` (`tr7/src/tr7-heap.ads:427-445`).
- Sweep safety: `Sweep` imports the closure postcondition, and
  `Marked_If_Reached` supplies the path induction that makes every reachable
  cell marked before the free guard (`tr7/src/tr7-reach.ads:30-114`).
- Root completeness by construction: `Collect_Garbage` roots the CEK state and
  every frame slot; the `Count <= 6*I + 5` invariant is machine-checked.
- No `pragma Assume`, `Annotate` or `Suppress` under `tr7/src`.

### Runtime-checked, not proved

- **Closure verification is a runtime gate.** The drain's completeness is not
  proved; the read-only scan turns a drain bug into “cycle abandoned, nothing
  freed”. This is the right failure direction and the docs say so, but the
  static theorem is conditional on the scan having run.
- `tr7_c` and `tr7i` are outside the proof; C ABI contracts are runtime checks.
- The safe-point discipline (only collect between steps) is a code-structure
  assumption, tested by stress GC, not a machine-checked semantic model.

### Trusted

- Every `tr7_c` body and the whole REPL are `SPARK_Mode => Off`.
- `Is_Aligned`/`Defaults_Written` are contract-support functions in the C
  boundary, so `Config_Init_Default`'s postcondition is verified by trusted
  code.
- `scripts/gen_abi.py` provides a useful mechanical guard, but `--check`
  compares generated text with generated text and therefore cannot catch a
  wrong comment inside the generator (see F20).

### Evidence and gate quality

- The on-disk summary matches the documented totals (1,228 initialization,
  12 non-aliasing, 730 run-time, 362 assertions, 1,156 functional, 113
  termination = 3,601; `Collect` 105 checks, `Sweep` 18,
  `Marked_If_Reached` 14).
- **`docs/verification.md` claims “0 warnings” but `gnatprove.out` reports two
  flow warnings**: `Tr7.Primitives.String_Compare` (line 247) and
  `Tr7.Primitives.Vector_Fill_Prim` (line 262). `prove.sh` greps only for
  `medium:`, `high:`, `unproved`, `failed`, so warnings do not fail the gate.
- `tr7/gnat.adc` (`Loop_Invariant => Ignore`) is load-bearing: the quantitative
  collector invariants are proof-only. The repository claims this policy was
  validated, but it is version-sensitive. On every GNATprove upgrade, flip the
  policy to `Check`, confirm the same obligation count, then flip it back; if a
  future release stops proving ignored invariants, the liveness claim would
  vanish without a red gate.
- The proof artifact lives under `obj/` and is git-ignored, so the audit's
  primary evidence is not in the repository.

## 3. Findings

Severity reflects user-visible impact and how hard the defect is to notice.
“Confirmed” means the lead review reproduced it with the current checked
build; “inspection” means both reviewers agree from the source but it was not
reproduced.

### Critical

None. No memory-safety, GC-soundness or proof-soundness defect was found.

### High

#### F1. Exact `/` drops the remaining operands after an inexact step, and rejects unary flonums
**Confirmed.** `Div_Prim` (`tr7/src/tr7-primitives.adb:2865-2873`) returns
immediately when `Acc mod Term /= 0`:

```ada
Acc_F := Long_Float (Acc) / Long_Float (Term);
Result := From_Flonum (Acc_F);
Status := No_Error;
return;                        -- the rest of the chain is never applied
```

Reproduced:

- `(/ 1 2 3)` → `0.5` (should be `1/6`)
- `(/ 6 4 2)` → `1.5` (should be `0.75`)
- `(/ 1 2 0)` → `0.5` (should be division-by-zero)

The `Len = 1` path calls `Get_Fixnum` unconditionally
(`tr7/src/tr7-primitives.adb:2760-2779`), so `(/ 2.0)` reports a type error
instead of `0.5`. `tests/div.scm` only covers all-exact chains or chains that
are inexact from the first operand, which is why this slipped through.

#### F2. Cyclic data hangs the interpreter outside the step limit
**Confirmed for `memv`, `assq`, and `case`; inspection for `map`/`do`.**
`Steps` is incremented only around `Step` (`tr7/src/tr7-machine.adb:3769-3793`);
a synchronous primitive or form walk does not advance it.

- `memq`/`memv`/`assq`/`assv` walk a list with no counter
  (`tr7/src/tr7-primitives.adb:2173-2250`, dispatch at `:4802-4806`).
  `(define c (cons (cons 'a 1) '())) (set-cdr! c c) (assq 'x c)` never returns.
- `Start_Case` scans clauses and datum lists in one step
  (`tr7/src/tr7-machine.adb:1677-1747`); a cyclic clause list hangs `eval`.
- `Start_Do`/`Do_Loop` (`tr7/src/tr7-machine.adb:1385-1421`,
  `1511-1544`) and `Map_Elements`/`Map_Next` (`:1753-1853`) have the same
  unbounded shape.
- `Reverse_List` and the quasiquote spine allocate per iteration, so they die
  with `heap exhausted` rather than hanging — but that is still a poor error
  for `(reverse cyc)`.

This is a denial-of-service/robustness defect, not memory corruption. The
project already bounds `list-tail`, `last-pair` and `vector-fill!`, so the
omission is inconsistent. `scripts/test.sh` has no timeout, so such a
regression hangs the gate.

#### F3. `write` does not produce readable data for strings or symbols
**Confirmed.** `Write_Internal` emits strings by copying raw characters
between quotes (`tr7/src/tr7-writer.adb:605-618`) and symbols as raw text
(`:602-604`). It does not escape `"`, `\`, newline or control characters, and
does not quote symbols that would read as another datum.

Reproduced: `(write "a\"b")` prints `"a"b"`. Also wrong by inspection:
`(write (string->symbol "a b"))` prints `a b`; the empty symbol prints
nothing; `(write (string->symbol "123"))` prints `123`, which reads as a
number. This breaks the core `read`/`write` contract for strings and symbols.

### Medium

#### F4. `expt` has the wrong sign for `-1` with a large odd exponent
**Confirmed by inspection.** The `N > 63` branch handles `A = 1` and `A = -1`
identically and returns `1` (`tr7/src/tr7-primitives.adb:2550-2561`), so
`(expt -1 65)` is `1` instead of `-1`. The `N <= 63` loop handles parity
correctly. Related: `remainder` of `Fixnum_Min` by `-1` reports overflow
(`Div_Guard`, `:2259-2272`) although the remainder `0` is representable.

#### F5. `#(...)` and `#u8(...)` are expression sugar, not datum literals
**Inspection.** The reader rewrites `#(...)` to `(vector ...)` and `#u8(...)`
to `(bytevector ...)` (`tr7/src/tr7-reader.adb:658-705`). Consequently
`'#((1 2) 3)` is the list `(vector (1 2) 3)`, not a vector; the writer emits
`#(1 2)`, but reading that text as a datum returns the list `(vector 1 2)`.
`tests/vectors.scm:13` encodes the current behaviour explicitly, so this is a
deliberate design choice — but it is a significant R7RS conformance deviation
and a read/write round-trip failure that belongs in the README's limitations.

#### F6. `append`, `string-append` and `string=?` are narrower than R7RS
**Confirmed for `string-append`; inspection for the rest.** `append` treats
every argument as a proper list (`tr7/src/tr7-primitives.adb:2021-2063`), so
`(append '(1) 2)` and `(append 1)` are type errors; R7RS allows any final
object and a single object. `string-append` requires exactly two arguments
(`:1462-1486`), so `(string-append)` and three arguments fail. `string=?`
requires exactly two (`:1522-1541`) while `string<?` and friends are variadic
(`:4193`).

#### F7. Named `let` is silently unsupported
**Confirmed.** `Eval_Pair` sends `let` straight to `Start_Let`
(`tr7/src/tr7-machine.adb:2402-2403`), which treats `cadr` as the bindings
list. `(let loop ((i 0)) ...)` therefore fails with `malformed expression`.
Named `let` is R7RS-small base and the idiomatic loop in the project's own test
style; neither README nor docs record its absence.

#### F8. `let`/`let*` do not create distinct locations for duplicate names
**Confirmed.** `Define` updates an existing binding in the current frame rather
than shadowing it (`tr7/src/tr7-env.adb:118-132`), and `Start_Let` reuses one
new environment for sequential bindings (`tr7/src/tr7-machine.adb:1054-1065`).
Therefore:

```scheme
(let* ((x 1) (f (lambda () x)) (x 2)) (f))   ; R7RS: 1, TR7: 2
```

`(let ((x 1) (x 2)) x)` returns `2` instead of reporting an invalid duplicate
binding. The existing `tests/forms.scm` rebinding test still passes because it
does not capture a closure across the rebinding.

#### F9. `map`/`for-each` truncate unequal lists instead of enforcing equal length
**Confirmed.** `Map_Next` stops when any list is empty
(`tr7/src/tr7-machine.adb:1837-1868`), so `(map + '(1 2) '(10))` returns
`(11)`; R7RS requires an error. The behaviour is bounded and deterministic, so
this is conformance, not safety.

#### F10. Float add/sub/mul guards produce false overflow at the boundary
**Confirmed.** The add/sub guard is `abs Acc < 1.0 or else abs Term < 1.0 or
else (both <= Last/2)` and the multiply guard uses `both <= 1.3e154`
(`tr7/src/tr7-primitives.adb:300-308`, `390-398`, `508-515`). The strict `<`
rejects representable results such as `(+ 1e308 1.0)`, `(- 1e308 1.0)`,
`(* 1e308 1.0)` and `(* 2e154 2)`, all of which report `exact integer
overflow` (the shared `Error_Overflow` label is itself misleading for flonums).
`docs/findings.md:252-255` claims "no false rejections for small operands",
which is inaccurate for magnitudes of 1.0–2.0.

#### F11. Environment lookup gives up after 1,024 parents and reports `Unbound`
**Inspection.** `Lookup`/`Set` iterate at most `Max_Env_Depth` contours
(`tr7/src/tr7-env.adb:150-171`, `189-211`). The depth equals lexical nesting at
closure creation, so a generator/Y-combinator style closure created inside
recursion can grow the chain without bound even with constant stack usage. Past
the limit a global lookup returns `Error_Unbound` — a wrong answer, not a
named limit.

#### F12. `tr7i` corrupts source lines longer than 4,096 characters; the REPL has no multi-line datum
**Confirmed for long lines.** `Get_Line (F, Line, Last)` with `Max_Line =
4_096` returns a full buffer without consuming the rest
(`tr7i/src/tr7i.adb:93-108`); the remainder is inserted after an artificial
LF. A long `;` comment line produces `parse error` in the current build; a
long string or token can be silently split. The REPL evaluates one line at a
time (`tr7i/src/tr7i.adb:155-172`), so multi-line datums are a parse error;
README advertises a REPL without recording this.

#### F13. GC low-water headroom is not sufficient for every single step
**Design risk from both reviewers.** `GC_Low_Water` is 512 and its comment says
it "leaves enough headroom for a whole step to allocate"
(`tr7/src/tr7-config.ads:25-30`). A single step can allocate more than that:
`list-copy`/`vector->list` up to two cells per element (2,048),
`make-vector` 1,024, a 256-binding `let` roughly 512 before the body starts. If
the free count is just above 512, no collection runs and the step fails with
`heap exhausted` even though garbage is available. This is robustness, not
safety; the comment is stronger than the code supports.

#### F14. Heap exhaustion during reading is reported as a parse error
**Confirmed by inspection.** `Read_Datum` has only `Read_Ok`/`Read_End`/
`Read_Error`; allocation failure becomes `Read_Error`, which `Engine.Evaluate`
maps to `Error_Parse` (`tr7/src/tr7-engine.adb:88-90`, `Read_Prim` at
`tr7/src/tr7-primitives.adb:1319-1325`). `docs/architecture.md:428-430` says a
datum larger than free space is reported as `heap exhausted`.

#### F15. Whole-`Cell` copies remain on the normal access path
**Inspection / performance.** `Fetch` copies the full `Cell`, including the
256-byte text buffer (`tr7/src/tr7-heap.adb:105-120`); `Car_Of`/`Cdr_Of` go
through it on every pair access (`tr7/src/tr7-pairs.adb:43-71`). `Fetch` is
`Inline`, so the compiler may scalarise the copy, but the source-level
aggregate remains. `Collect_Garbage (M : Machine)` takes the whole machine
record by value (`tr7/src/tr7-machine.ads:135-138`), which expresses a large
copy at every collection; GNAT may pass large `in` records by reference, but
this should be measured or replaced by a small root projection. The project's
own profile already identified whole-cell copies as a dominant cost
(`docs/findings.md:464-469`).

#### F16. `call/cc` in tail position is not a proper tail call
**Inspection.** Each dynamic extent holds `K_CallCC` + `K_CallCC_Recv` frames
for the duration of the procedure (`tr7/src/tr7-machine.adb:3293-3315`), so
recursion through `(call/cc (lambda (k) (f ...)))` consumes two stack frames
per level and dies at the step limit. README/architecture claim tail calls
push no frame without recording this exception.

#### F17. Verification and documentation overclaims
Both reviewers independently found these; all re-checked:

- `docs/verification.md:83-84,108-109` says every unit reports 0 warnings and
  the build is warning-free; `gnatprove.out` has two flow warnings (F-ver above).
- `docs/verification.md:127-130` says every public `tr7` operation has a
  Pre/Post pair or is a total expression function; several operations are
  Pre-only (`Kind_Of`, `Car_Of`, `Cdr_Of`, `Lookup`, most constructors), so
  “Pre/Post pair” does not mean functional correctness.
- `scripts/test.sh:15` enumerates **45** `.scm` suites, while `README.md:13`
  and `docs/plan.md:9` say 48; the docs do not explain the counting convention.
- `docs/plan.md:17-19` still lists `syntax-rules` and `import` as outside v1
  while later sections describe the implemented subset and compatibility shim.
- `docs/plan.md:150` says about 11.5k lines in `tr7/src`; `wc -l` gives 14,162.
- `tr7/src/tr7.ads` has no `SPARK_Mode => On`, while verification says every
  unit under `tr7/src` is in SPARK mode. The root package has no declarations,
  so impact is nil, but the claim is not literal.
- `tr7/gnat.adc` is `Loop_Invariant => Ignore`, while
  `docs/findings.md:422-425` says the checked profile keeps quantified
  invariants live on purpose; the performance narrative is stale.
- `scripts/gen_abi.py:143` emits `${len(stubs)} of ${len(decls)} ... are
  implemented`, so `tr7_c/src/tr7_c_stubs.c` claims 177 of 183 are implemented
  when 177 are stubs and six are implemented. `--check` compares generated text
  to generated text and cannot catch this.
- `docs/architecture.md:428-430` conflates heap exhaustion with parse errors
  (F14).

### Low / Nit

- **Reader surface gaps (GLM L3, DS low):** no `#true`/`#false`, `#;` datum
  comments, `#|...|#` block comments, bar-quoted symbols, `#\alarm`/`#\delete`
  names, or `\x...;` string escapes. `#tfoo` reads as `#t` then `foo` because
  the boolean branches do not require a delimiter. `.` alone is a symbol.
- **`case` with `=>` (GLM L4, DS low):** `Start_Case` would evaluate `=>` as
  an unbound symbol. Reproduced: `(case 1 ((1) => (lambda (x) x)))` →
  unbound variable.
- **Empty lambda body (GLM L5, DS low):** `(lambda (x))` returns
  `#<unspecified>` instead of being rejected. Reproduced.
- **Extra operands silently ignored (DS low):** `(if t 1 2 3)`, `(quote a b)`,
  extra `define`/`set!` forms read only the fields they need.
- **`+inf.0`/`-inf.0`/`+nan.0` are written but unreadable** (GLM L2): the
  reader interns them as symbols, so the writer round-trip claim holds only
  for finite values.
- **`Put_Hex` prints nothing for zero** (`tr7/src/tr7-writer.adb:37-63`).
  Not reachable for a character today (zero takes the byte path), but a latent
  trap for future callers.
- **`GC_Stress_Every = 8` but collection happens on the ninth safe point**
  (`tr7/src/tr7-config.ads:32-36`, `tr7/src/tr7-machine.adb:3759-3784`);
  `scripts/bench.sh:29` says "every 9th". Comment/constant disagree.
- **`Error_Overflow` is labelled "exact integer overflow"** even for flonum
  paths (`tr7/src/tr7-runtime.adb:66`); the reports above hit this label.
- **`define-syntax` does not require a symbol name** (GLM M7): it checks only
  `Is_Handle (Name)`, so `(define-syntax (x) ...)` installs a binding keyed by
  a pair and leaves it in the global environment.
- **`tr7_c` host misuse can fault (DS low):** `Engine_Create`/`Load_String`
  trust any aligned pointer (`tr7/src/tr7_c.adb:125-144`, `:202-203`), and
  `Get_Id` can return null on allocation failure despite its non-null
  postcondition (`tr7_c/src/tr7_c.adb:86-95`). Documented as trusted boundary.
- **`Collect_Garbage` zeroes the 24,581-entry `Root_Array` every call**
  (GLM Nit 3), part of the idle-collection cost.
- **Values wrapper undetectability (GLM Nit 1):** a `Cell_Values` wrapper can
  leak into a single-value context and there is no `values?` predicate.
- **`Is_Aligned` check reuse (GLM Nit 2):** `Engine'Alignment` is also used to
  validate config pointers; correct on the tested ABI but conceptually two
  different facts.
- **`docs/M5-TASK.md:56` says `Max_Cells` rounds are enough to drain**, while
  the code deliberately uses `Max_Cells + 1` (`tr7/src/tr7-heap.adb:620`).

## 4. Test coverage gaps

The suites are broad for ordinary use but miss exactly the classes above.

1. Non-exact multi-term `/` (`(/ 1 2 3)`, `(/ 6 4 2)`, `(/ 1 2 0)`) and
   unary `(/ 2.0)`.
2. `expt` with `-1` and odd exponents above 63; `remainder`/`quotient` at
   `Fixnum_Min` and `-1`.
3. Cyclic `memq`/`memv`/`assq`/`assv`, and `eval` of constructed cyclic `case`
   and `do` forms; a harness-level timeout so hangs fail the gate.
4. Writer/reader round-trip for strings containing `"`, `\`, newline and
   control characters; symbols made by `string->symbol` (spaces, empty,
   numeric-looking).
5. `read`/`write` of vectors and bytevectors, including quoted literals.
6. Variadic `append`, `string-append`, `string=?`; improper final `append`.
7. `map`/`for-each` with unequal list lengths.
8. `let*` closure capture across duplicate bindings; duplicate `let`/lambda
   parameter names.
9. Malformed special forms with extra operands.
10. Heap-exhaustion and `Mark_Failed` paths, including a single step that needs
    more than `GC_Low_Water` cells.
11. C ABI negative cases: null config, aligned-but-invalid pointers, null
    command, invalid allocator pair, and every generated stub returning zero.
12. Deep environment chains (>1,024 contours).
13. Long-line and CRLF scripts for `tr7i`.
14. Differential testing against upstream C TR7; the plan mentions it as
    optional, but no script or oracle exists in the repository.

## 5. Prioritized recommendations

1. **Fix `/` (F1), `expt` (F4) and the remainder edge case**, and add the
   missing arithmetic tests before claiming numeric conformance.
2. **Bound every user-data walk (F2).** Reuse the `Left`-counter idiom already
   used in `Is_Literal`/`Last_Pair_Prim`; add it to `memq`/`assq`/`memv`/`assv`,
   `Start_Case`, `Start_Do`/`Do_Loop` and `Map_Elements`; give `Reverse_List`
   callers a `Max_List_Length` guard. Add timeouts to `scripts/test.sh`.
3. **Make the writer readable (F3),** escaping strings and symbols, or define
   and document an explicit implementation-specific printing rule; add
   round-trip tests.
4. **Settle vector/bytevector literals (F5):** either construct true datum
   literals in the reader or document that `#(...)`/`#u8(...)` are expression
   sugar and that writer output is not `read`-round-trippable.
5. **Close the conformance gaps** in F6–F9: variadic `append`/`string-append`/
   `string=?`, named `let`, duplicate-binding locations, equal-length `map`.
6. **Relax the float guards at equality (F10)** and add boundary tests; update
   the findings narrative.
7. **Harden GC headroom (F13)** or make the comment and capacity reasoning
   match the code; add a heap-exhaustion test.
8. **Fix `tr7i` line handling (F12)** and add a long-line test.
9. **Correct verification/documentation claims (F17):** warnings, suite count,
   root list, `gnat.adc` narrative, `tr7.ads` SPARK mode, heap-vs-parse error,
   generated stub comment, line count. Make `prove.sh` fail on warnings.
10. **Reduce whole-cell copying (F15)** with field-level accessors and measure
    the machine-record passing cost.
11. **Add the policy-flip proof check** described in §2 and commit a summary
    of `gnatprove.out` so the audit evidence lives in the repository.
12. **Run one upstream differential session** on the shared subset; it is the
    cheapest way to find the remaining conformance drift.

---

## 6. Bottom line

The collector and its proof are the strongest part of the project; neither
reviewer could construct a counterexample to “live data is never freed” at any
layer. The weakest axes are cyclic-input robustness, arithmetic edge cases, and
writer/conformance accuracy. All of the high-severity findings are local fixes
that do not disturb the proof structure; the verification story itself is sound
but currently described more strongly than the evidence supports.

## 7. Resolution (follow-up)

The findings above were addressed in the follow-up pass; the accepted gate is
now 3,963 checks, 0 unproved/justified, 0 flow warnings, and 47 suites (each
also run under stress GC).

Fixed with regressions:

- **F1** `/` folds the whole chain after the first inexact step, and unary
  flonum division works; `Div_Float` has a functional postcondition.
- **F2** `memq`/`memv`/`assq`/`assv`, `case`, `do` and `map` walks are bounded;
  cyclic inputs now report `malformed expression`/`type error`. `test.sh` has
  a 30 s timeout, and `bad-cycle.scm`/`bad-map.scm` cover the cases.
- **F3** `write` escapes strings and bar-quotes symbols; the reader supports
  `|...|`, `\a`, `\b`, `\x...;`, `#true`, `#false`, `#|...|#` and `#;`.
- **F4** `expt` keeps the sign of `-1` for large odd exponents; `remainder` and
  `modulo` of `Fixnum_Min` by `-1` return `0`.
- **F5** `#(...)`/`#u8(...)` are true vector/bytevector datums; writer output
  reads back.
- **F6** `append` accepts a non-list final argument; `string-append` and
  `string=?` are variadic.
- **F7** named `let` is a `letrec` rewrite and is tested.
- **F8** `let*` is a nested-`let` rewrite, so closures capture the earlier
  binding location.
- **F9** `map`/`for-each` reject unequal-length lists.
- **F10** the float guards accept equality at the safe boundary; boundary
  tests were added.
- **F11** environment-depth exhaustion reports `environment too deep`, not
  `unbound`.
- **F12** `tr7i` reads whole lines (line buffer = `Max_Source`); long-line and
  CRLF regressions are in `test.sh`.
- **F13** the low-water comment now describes the heuristic honestly.
- **F14** reader allocation failure has its own `Read_Heap_Full` status and
  maps to `heap exhausted`.
- **F17** the verification claims were corrected: warning scan in
  `prove.sh`, 47-suite count, ~15k line count, `tr7.ads` SPARK mode, stub
  comment, `gnat.adc` narrative, root-list description, contract wording.
- Low items fixed: `case =>`, empty lambda bodies, extra operands on
  `quote`/`if`/`set!`, `define-syntax` name checking, `values?`, `Put_Hex 0`,
  `GC_Stress_Every` cadence.

Deferred and documented rather than silently left:

- **F15** addressed: `Pair_Car`, `Pair_Cdr`, `Pair_Fields`,
  `Environment_Fields` and `Environment_Bindings` read only the fields the hot
  paths need; pair access and environment lookup no longer materialise the
  256-byte text buffer.
- **F16** correction: the implementation holds **one** `K_CallCC_Recv` frame
  per dynamic extent, not two (`K_CallCC` is converted in place).  That frame
  is still what makes an invocation find its extent, so recursion through
  `call/cc` is not a proper tail call; removing it needs a different
  continuation representation.
- `+inf.0`/`-inf.0`/`+nan.0` are still written but not read.  The core's
  arithmetic guards keep non-finite values out of normal execution, and
  accepting them in the reader would need either a trusted
  `Unchecked_Conversion` in the verified core or a non-IEEE assumption;
  both are design decisions left for later.
- C ABI host pointers are now validated for null and correct alignment before
  use, with separate engine/config alignment checks; the remaining C pointer
  trust is the documented boundary.
